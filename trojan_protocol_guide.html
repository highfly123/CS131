一、为什么需要 Trojan？（背景故事）

想象一下，你住在一个小区里，物业会检查所有进出的快递包裹。如果你的包裹是透明的（HTTP明文），物业一眼就能看到里面装了什么。

📖 故事比喻

HTTP 明文时代：就像在"明信片"上写东西——邮递员、邻居、任何经手的人都能看到内容。

所有人的网络流量都像透明的水管，中间任何节点都能看到你在访问什么、发送什么数据。

Shadowsocks 的 HTTP 伪装为什么不够？

早期的加密代理（如 Shadowsocks）就像是把信封涂上了一层颜料——虽然看不到内容了，但这个"涂了颜料的信封"本身就很可疑！

检查系统心想："正常人谁会把信封涂成这样？这肯定有问题！"

💡 核心结论

Trojan 的思路：不要"伪装"成 HTTPS，而是直接"就是" HTTPS！

就像间谍电影里——最好的伪装不是化妆，而是根本就是那个身份。

类比：

  • "在信封外面写假地址" → 依然是个可疑的信封（SS伪装）
  • "直接变成一封普普通通的信" → 没人会多看一眼（Trojan）

二、HTTPS 到底是什么？（大白话版）

在理解 Trojan 之前，我们必须先搞清楚 HTTPS 是什么。别担心，我们用最简单的比喻来讲！

🎭 一句话理解

HTTP = 明信片 📮（谁都能看到你写了什么）

HTTPS = 密封的信 ✉️（只有收件人能拆开看）

HTTPS = HTTP + TLS（给明信片套了一层加密的信封）

当你在浏览器地址栏看到 https:// 和一个小锁图标 🔒 时，就表示这个连接是加密的。你的密码、聊天记录等敏感信息，中间的任何人（WiFi 管理员、运营商等）都看不到具体内容。

🔑 关键点

现在互联网上超过 90% 的流量都是 HTTPS。这意味着 HTTPS 是"最不起眼"的流量类型——这正是 Trojan 利用的关键！

三、加密基础 — 对称加密 vs 非对称加密

要理解 TLS 怎么工作，我们需要先了解两种加密方式。放心，我们用"锁箱子"来讲，超级好懂！

🔐 对称加密：一把钥匙

比喻：你和朋友约定了一把"暗号钥匙"，用它来锁箱子。你们俩都有这把钥匙，所以都能锁、都能开。

优点：加密/解密速度很快 ⚡

问题：钥匙怎么安全地传给对方？如果在传钥匙的过程中被截获，那加密就白费了！

🔑 非对称加密：一对钥匙

比喻：你制作了一个特殊的"锁头"（公钥）和"钥匙"（私钥）。

  • 公钥（锁头）：你可以发给任何人，谁都能用它锁箱子
  • 私钥（钥匙）：只有你自己有，只有你能打开箱子

优点：不用传"钥匙"，只传"锁头"，即使锁头被截获也无所谓

问题：加密/解密速度比较慢 🐢

✅ 小结

TLS 的精妙之处在于：用非对称加密安全地交换钥匙（解决了钥匙传递问题），然后用对称加密高速通信（解决了速度问题）。两全其美！

四、网站证书与 CA 机构

非对称加密解决了传输安全的问题，但还有一个问题：你怎么确定对面真的是你想连的服务器？

🏦 银行的比喻

假设你去银行办事，有人在路边摆了个摊，说"我就是银行"——你信吗？

你不信。你要看它有没有营业执照。而这个执照是谁发的？是工商局（权威机构）发的。

在网络世界里：

  • 营业执照 = TLS 证书
  • 工商局 = CA（证书颁发机构）

为什么需要证书？

没有证书，攻击者可以冒充任何网站（中间人攻击）。有了证书体系，浏览器可以验证"这个网站确实是它声称的那个网站"。

证书里有什么？

  • 📍 域名：这个证书属于哪个网站（如 example.com）
  • 🔑 公钥：网站的公钥，客户端用它加密数据
  • 📅 有效期：证书什么时候过期
  • ✍️ CA 签名：CA 机构的"盖章"，证明这个证书是真的

申请证书的过程（概念）

简单来说：你需要向 CA 证明你真的拥有这个域名。CA 会通过各种方式验证（比如让你在网站上放一个特定文件，或者设置一条 DNS 记录）。验证通过后，CA 给你签发证书。

常见的免费 CA：Let's Encrypt、ZeroSSL 等。

✅ 信任链原理

浏览器信任根 CA → 根 CA 信任中间 CA → 中间 CA 为你的网站背书。
一层一层向上追溯，最终追溯到浏览器/操作系统预装的根证书。

五、TLS 握手过程（图解）

好了，现在我们把前面学到的东西串起来！当你的浏览器连接一个 HTTPS 网站时，会发生以下"握手"过程：

1 Client Hello（客户端打招呼）

浏览器说："你好！我支持这些加密方式，我想访问 example.com（这就是 SNI）"

2 Server Hello + 证书（服务器回应）

服务器说："好的，我们用这个加密方式。这是我的证书（里面有我的公钥）。"

3 客户端验证证书

浏览器检查：证书是否由可信CA签发？域名对不对？有没有过期？一切OK才继续。

4 交换会话密钥

客户端生成一个随机的"会话密钥"，用服务器的公钥加密后发过去。只有服务器的私钥能解开。

5 🎉 加密通信开始！

双方都有了会话密钥，之后的所有数据都用对称加密传输。速度快、安全！

⚠️ SNI 的问题

注意第①步：客户端在还没加密的时候，就把要访问的域名（SNI）发出去了！

这意味着中间人虽然看不到你传的内容，但能看到你要访问哪个网站。

这是目前 TLS 的一个"缺陷"，后面会详细讲它对 Trojan 的影响。

六、Trojan 的核心原理 — "瞒天过海"

终于到了主角登场！前面铺垫了这么多，就是为了理解 Trojan 的精妙设计。

🌲 核心思想

"想藏一棵树，最好的地方是森林。"

互联网上最多的流量是什么？HTTPS！

Trojan 不发明新的加密方式，它直接使用真正的 TLS/HTTPS。在外面看来，Trojan 的流量和你访问淘宝、刷微博的流量一模一样！

🔑 密码机制

那 Trojan 服务器怎么区分"正常访客"和"代理用户"呢？

秘密在于：在 TLS 加密隧道建立之后，Trojan 客户端会在第一个数据包里发送一个预设的密码（password）。

因为这个密码是在加密隧道内部传输的，外部观察者完全看不到！

  • 密码正确 → 你是自己人，开始代理转发
  • 密码错误 → 当作普通访客，返回正常网页

💡 为什么防火墙分辨不了？

因为 Trojan 使用的是真正的 TLS 证书、真正的 443 端口、标准的 TLS 握手。

从外部看，它和你访问百度、Google 的 HTTPS 连接没有任何区别——因为它本来就是标准 HTTPS！

七、Trojan 的防探测机制（回落/Fallback）

聪明的检测系统可能会主动连接你的服务器来"试探"。Trojan 的回落机制就是应对这种"主动探测"的杀手锏。

🎭 比喻：带密室的咖啡店

想象一家咖啡店，表面上就是个正常的咖啡店。但如果你跟店员说出正确的暗号，你就能进入后面的密室。

如果暗号不对？没关系，你就是个正常客人，给你一杯咖啡。

如果有人来检查？他看到的就是一家正常的咖啡店！

🧠 为什么这很巧妙？

  • 主动探测？访问到的就是一个真正的网站，看不出任何异常
  • 统计分析？服务器确实在提供网页服务，流量特征完全正常
  • 真正的用户？密码一对，无缝切换成代理模式

这就是为什么 Trojan 被称为"最像正常流量"的协议——因为它本身就是正常流量的一部分！

八、SNI 的重要性与风险

还记得 TLS 握手第一步中的 SNI（Server Name Indication）吗？这是 Trojan 目前最大的弱点。

🚨 SNI 是什么问题？

在 TLS 握手的最开始，客户端需要告诉服务器"我要访问哪个域名"——而这个信息是明文的！

这意味着防火墙虽然看不到你传输的内容，但能看到你在连接哪个域名。

应对策略

  • 🎭 使用普通域名：不要用 proxy.xxx.com 这种一看就很可疑的域名
  • 🤫 不要公开分享：一旦太多人用同一个域名，容易引起注意
  • 🌐 搭配 CDN：用 CDN 可以"隐藏"真实服务器 IP
  • 🔮 未来技术 — ECH（Encrypted Client Hello）：把 SNI 也加密！目前还在推广中

🔮 ECH — 未来的解决方案

Encrypted Client Hello (ECH) 是 TLS 1.3 的扩展，目标是把 SNI 也加密起来。

一旦 ECH 普及，防火墙连"你在连谁"都看不到了。但目前支持还不完善，需要更多时间推广。

关于每一步的解释

为什么需要域名？ 因为 TLS 证书是绑定域名的。没有域名就无法获得正规 CA 颁发的证书。

为什么需要证书？ 没有证书，TLS 握手无法完成，客户端会报错。而且有了证书，外部看来你就是一个正常的 HTTPS 网站。

为什么需要回落网站？ 这是"防探测"的核心——让任何探测者看到的都是一个正常网站。

自签证书可以吗？ 可以，但客户端需要跳过证书验证，而且缺少 CA 背书，有一定的安全风险和识别风险。

十、知识测验 + 总结

📝 测试一下你学到了多少！

问题 1：Trojan 为什么选择"伪装"成 HTTPS 流量？

✅ 答案：B
HTTPS 占互联网流量的 90% 以上。"想藏一棵树，最好的地方是森林"——Trojan 让自己的流量和千千万万的正常 HTTPS 请求混在一起，无法被区分。

问题 2：TLS 握手中的 SNI 字段有什么安全隐患？

✅ 答案：B
SNI（Server Name Indication）在 TLS 握手的开始阶段以明文发送，告知服务器客户端想连接哪个域名。这意味着中间人可以看到你在访问哪个网站（但看不到具体内容）。

问题 3：Trojan 的"回落"（Fallback）机制的作用是什么？

✅ 答案：B
回落机制是 Trojan 的精妙设计：如果有人（包括主动探测系统）连接时没有提供正确的密码，服务器就表现得像一个普通的网站，返回正常的网页内容。这样探测者无法判断这是一个代理服务器。

问题 4：为什么 Trojan 需要一个真正的 TLS 证书？

✅ 答案：B
使用正规 CA 颁发的证书可以让 Trojan 服务器的 TLS 握手过程与任何正常 HTTPS 网站完全一致。如果用自签证书，虽然也能用，但 TLS 行为可能有细微差异，增加被识别的风险。

问题 5：TLS 为什么要"先非对称、后对称"地加密？

✅ 答案：A
非对称加密安全但慢，对称加密快但需要"提前约好钥匙"。TLS 的聪明做法：先用非对称加密安全地交换一个对称密钥，然后用这个对称密钥进行快速的通信加密。两者优势互补！

🔮 未来方向

技术在不断演进，以下是一些新兴协议/技术：

  • VLESS：更轻量的协议，去掉了多余的加密层（因为 TLS 本身已经加密了）
  • Reality：解决了 SNI 和证书问题，可以"借用"其他网站的证书！更难被识别
  • ECH：加密 SNI，从根本上解决域名泄露问题

🎓 总结

恭喜你读到这里！让我们回顾一下核心知识：

  1. Trojan 利用真正的 HTTPS/TLS 来隐藏代理流量
  2. TLS = 非对称加密握手 + 对称加密通信
  3. 证书由 CA 颁发，确保服务器身份可信
  4. 回落机制让服务器在探测面前表现为正常网站
  5. SNI 是当前主要弱点，ECH 是未来的解决方案

附录：SOCKS5 代理 vs HTTP/HTTPS 代理 — 到底该配哪个？

很多代理软件（如 Clash、V2Ray、Trojan 客户端）启动后会同时提供 SOCKS5 和 HTTP/HTTPS 两种代理接口。你在配置其他软件时，到底该填哪个？让我们搞清楚。

🎭 一个比喻

想象你要把一个包裹交给快递员帮你转发：

  • HTTP 代理：像一个"翻译中介"——它会打开你的包裹看一下内容（理解 HTTP 协议），然后重新打包帮你转发。它只认识"网页请求"这种包裹。
  • SOCKS5 代理：像一个"万能快递员"——你给它什么包裹它就转发什么，不管里面是什么内容、什么格式。它不打开，也不需要理解。

📡 SOCKS5 代理

  • 工作在传输层（更底层）
  • 支持任意协议：HTTP、FTP、SMTP、游戏、P2P...
  • 不解析流量内容，只负责转发
  • 支持 TCP 和 UDP
  • 更通用、更强大
  • 默认端口通常：1080

🌐 HTTP/HTTPS 代理

  • 工作在应用层（更上层）
  • 只支持 HTTP/HTTPS 协议
  • 能理解 HTTP 请求，可以做缓存/过滤
  • HTTPS 通过 CONNECT 方法隧道转发
  • 兼容性好，几乎所有软件都支持
  • 默认端口通常：7890 或 8080

🤔 到底该配哪一个？

✅ 简单结论

场景 推荐配置 原因
浏览器 SOCKS5 或 HTTP 都行 浏览器两种都支持很好
终端工具（curl/wget/git） HTTP 代理优先 终端环境变量 http_proxy 是最通用的
npm / pip / apt HTTP 代理 包管理器通常只支持 HTTP 代理
游戏 / 语音软件 SOCKS5 需要 UDP 支持，HTTP 代理不行
Telegram / Discord SOCKS5 优先 这些软件的SOCKS5支持更完善
不确定 / 通用配置 两个都配 让软件自动选择最合适的

💡 最佳实践：两个都配！

大多数代理客户端（Clash、V2Ray等）会同时提供 SOCKS5 和 HTTP 两种端口。例如：

  • SOCKS5 → 127.0.0.1:1080
  • HTTP → 127.0.0.1:7890

当一个软件让你配置代理时：

  1. 如果它同时有 SOCKS5 和 HTTP 两个选项 → 两个都填（各填各的端口）
  2. 如果只有一个选项 → 看它支持什么就填什么
  3. 如果是终端/命令行工具 → 优先设置 HTTP 代理（兼容性最好）
  4. 如果是需要 UDP 的应用 → 必须用 SOCKS5

🎯 一句话记忆法

HTTP 代理像 "专门送网页快递的" — 大部分日常工具都认它

SOCKS5 代理像 "什么都送的万能快递" — 更强大，但不是所有软件都知道怎么用它

能配两个就两个都配，让软件自己选择走哪条路！

HTTP 代理 和 HTTPS 代理 有什么区别？

容易混淆的点：

  • "HTTP 代理" 是代理类型的名字——它可以代理 HTTP 和 HTTPS 流量
  • 当代理 HTTPS 流量时，用的是 CONNECT 方法建立隧道，不解密内容
  • 所以你在软件里看到 "HTTP代理" 的设置项，填进去以后它也能代理 HTTPS 网站
  • 不用担心"我填了 HTTP 代理是不是只能访问 HTTP 网站"——不是的！

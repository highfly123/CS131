① 五层协议模型总览

互联网采用 TCP/IP 五层模型，每一层只和紧邻的上下层通信，职责清晰。 数据从应用层向下逐层 封装（Encapsulation），到达对端后再逐层 解封装（Decapsulation）。

② 整体网络拓扑

以访问 https://www.example.com 为例，数据包要经历以下节点：

💻 你的电脑 — 发起请求，IP: 192.168.1.5，有唯一 MAC 地址
🔀 交换机 — 局域网内根据 MAC 表转发帧，不查 IP
🏠 家庭路由器 — 做 NAT，把私有 IP 转为公网 IP
📡 ISP 路由器 — 运营商网络，维护路由表（BGP）
🔄 骨干路由器 — 超高速转发，跨大洲互联
🖥️ Web 服务器 — 最终目标，返回 HTML 页面
③ 全流程分步详解

🖊️ 在浏览器输入 https://www.example.com 并按回车

浏览器首先解析 URL 结构：

  • https → 协议（HTTPS = HTTP + TLS/SSL 加密）
  • www.example.com → 主机名（域名）
  • 路径默认为 /
  • 端口默认 443（HTTPS）
浏览器检查本地缓存（磁盘/内存），如果有缓存且未过期，直接使用缓存，跳过 DNS 查询。

🔍 DNS 域名解析 — 把域名翻译成 IP 地址

DNS（Domain Name System）是互联网的"电话簿"。解析顺序：

  • 1 查 浏览器 DNS 缓存
  • 2 查 操作系统 DNS 缓存（Windows: ipconfig /displaydns）
  • 3 查 本机 hosts 文件（/etc/hosts 或 C:\Windows\System32\drivers\etc\hosts）
  • 4 以上都没有 → 向 本地 DNS 解析器（递归解析器，通常由 ISP 提供，或 8.8.8.8）发送 UDP 查询

🔢 子网判断 — 目标 IP 是否在同一局域网？

拿到目标 IP 93.184.216.34 后，操作系统要判断目标是否在同一子网：

本机 IP： 192.168.1.5
子网掩码： 255.255.255.0 （即 /24）
本机网络号： 192.168.1.5 AND 255.255.255.0 = 192.168.1.0
目标网络号： 93.184.216.34 AND 255.255.255.0 = 93.184.216.0
结论： 不在同一子网！ → 数据包需要发往 默认网关（家庭路由器 192.168.1.1）

如果在同一子网（例如访问 192.168.1.10），则直接在局域网内用 ARP 找到对方 MAC 地址通信。

📢 ARP 协议 — 用 IP 找 MAC 地址

数据链路层传输帧需要 MAC 地址。操作系统需要知道默认网关（192.168.1.1）的 MAC 地址：

  • 先查 ARP 缓存表（arp -a 命令可查看），如果有则直接使用
  • 没有则广播 ARP 请求报文
ARP 请求（广播）：
"局域网里所有人注意！我是 192.168.1.5（MAC: AA:BB:CC:11:22:33）， 谁是 IP 192.168.1.1？请告诉我你的 MAC！"
目标 MAC = FF:FF:FF:FF:FF:FF（全局广播）
ARP 回应（单播）：
路由器回复："我是 192.168.1.1，我的 MAC 是 DD:EE:FF:44:55:66"

ARP 记录会缓存约 20 分钟，避免每次都广播。

ARP 缓存表示例：

④ 交换机 vs 路由器 — 两种转发设备

🔀 交换机（Switch）— 工作在第 2 层

  • 维护 MAC 地址表（CAM Table）
  • 学习：收到帧时记录 源 MAC → 端口
  • 转发：查目标 MAC，找到对应端口就单播，找不到就 泛洪（Flood） 所有端口
  • 不跨网络，只在同一局域网内工作
  • 转发速度极快（硬件级，纳秒级）

🏠 路由器（Router）— 工作在第 3 层

  • 维护 路由表（Routing Table）
  • 根据目标 IP 地址 查路由表，决定下一跳
  • 每跳都重新封装以太网帧（更新 MAC 地址）
  • TTL 每经过一个路由器减 1，TTL=0 时丢包
  • 家庭路由器还兼做 NAT、DHCP、防火墙

📊 路由表示例 — 家庭路由器如何决定下一跳

目标 IP: 93.184.216.34，路由器逐行匹配，选最长前缀匹配：

目标网络子网掩码下一跳接口协议
192.168.1.0/24直连eth1 (LAN)直连
10.0.0.0/8直连eth2直连
0.0.0.0/0 （默认路由）203.x.x.1 (ISP)eth0 (WAN) ✅静态
93.184.216.34 不匹配任何具体路由 → 命中 默认路由 0.0.0.0/0 → 发往 ISP 路由器。
这就是"最长前缀匹配"原则：匹配前缀最长（最具体）的路由优先。

🔄 NAT — 网络地址转换

家庭路由器只有一个公网 IP，需要 NAT 让多台设备共享：

出去时（SNAT）：
src IP: 192.168.1.5:54321
→ 替换为公网 IP: 203.x.x.5:12345
记录到 NAT 映射表
⇄
回来时（DNAT）：
dst IP: 203.x.x.5:12345
→ 查 NAT 表还原为: 192.168.1.5:54321
转发回你的电脑
⑤ TCP 三次握手 — 建立可靠连接

IP 层只管"尽力而为"投递，TCP 在其上提供可靠、有序、有校验的传输。 建立连接前必须完成三次握手：

为什么要三次握手？
两次握手无法防止"历史连接"的误建立；三次握手确保双方都有发送和接收能力。
序列号的作用
TCP 将数据分成多个段，序列号保证按序重组，丢包时精确重传。
端口号
客户端随机端口（>1024），服务器 443（HTTPS）。五元组唯一标识一条连接。
⑥ TLS 握手 + HTTP 请求/响应

🔐 TLS 握手（HTTPS 加密层）

TCP 连接建立后，HTTPS 还需要 TLS 握手（以 TLS 1.3 为例）：

① ClientHello

客户端发送：支持的 TLS 版本、支持的加密套件列表、随机数 Client Random

② ServerHello + 证书

服务器返回：选定加密套件、随机数 Server Random、数字证书（含服务器公钥，由 CA 签名）

③ 验证证书 + 密钥协商

客户端验证证书链（根 CA → 中间 CA → 服务器证书），使用 ECDH 密钥交换算法协商出对称密钥（Session Key）。TLS 1.3 仅需 1-RTT。

④ 加密通信开始

双方使用 AES-256-GCM 等对称加密算法，用 Session Key 加/解密所有后续数据。

📨 HTTP/2 请求与响应

TLS 握手完成后，浏览器发送 HTTP 请求：

请求报文：

HTTP/2 支持 多路复用：一条 TCP 连接上并行发送多个请求，大幅减少延迟。

⑦ 数据包的跨网旅程 — MAC 地址逐跳更新

IP 地址像收件人地址（全程不变），MAC 地址像快递员工号（每段路程都换人）。

📝 每一跳路由器的工作流程

  1. 收到以太网帧 → 验证 FCS 校验和，丢弃损坏帧
  2. 剥掉以太网帧头（第2层）
  3. 取出 IP 数据包，查路由表，找到下一跳 IP
  4. TTL 减 1；若 TTL = 0，丢包并向发送方发 ICMP "Time Exceeded"
  5. 用 ARP 查下一跳的 MAC 地址
  6. 重新封装以太网帧（新的 src/dst MAC），发出

⑩ 核心要点总结

🎯 IP 地址 vs MAC 地址

IP 地址（逻辑地址）：全程标识源和目标，可以跨网络路由，可以动态分配（DHCP）。

MAC 地址（物理地址）：硬件烧录，全球唯一，只在当前网段（同一广播域）内有效，每经过一个路由器就更换。

🔗 子网划分本质

IP 地址 = 网络号 + 主机号。子网掩码用来"与运算"分离两者。
/24 = 255.255.255.0 → 同一子网最多 254 台主机。
路由器根据网络号跨子网转发，交换机在子网内转发。

🔄 NAT 的代价

NAT 解决了 IPv4 地址耗尽问题，但破坏了端到端透明性，导致 P2P 穿透困难。IPv6 地址空间足够大（128位），理论上不需要 NAT。

⚡ 现代优化

CDN：将内容缓存到离用户最近的节点，减少RTT。
HTTP/3 (QUIC)：基于 UDP，解决 TCP 队头阻塞。
DNS 预解析：<link rel="dns-prefetch"> 提前解析。
TLS 1.3：1-RTT 握手，比 TLS 1.2 快一倍。

🔍 traceroute 原理

发送 TTL=1,2,3... 的 UDP/ICMP 包，每个路由器 TTL 减 1，到 0 时返回 ICMP Time Exceeded，从而探测每一跳路由器的 IP 和延迟。

🌍 BGP — 互联网路由协议

ISP 之间使用 BGP（边界网关协议） 交换路由信息，形成互联网路由表（全球约 90 万条前缀）。BGP 是互联网的"骨架"，也是安全薄弱环节（BGP 劫持）。
